# VPS Disk Management — Cleanup Reference

## What's safe to delete (recreates automatically)

| Item | Typical size | Recreate method |
|------|-------------|----------------|
| Builder profile sessions | 3G | Generated by subagent delegation; safe to `rm -rf ~/.hermes/profiles/builder/sessions/` |
| Hermes state snapshots | 666M | Old auto-backups; safe to `rm -rf ~/.hermes/state-snapshots/` |
| `uv cache` | 2.3G | `uv cache clean` — redownloads on next `uv pip install` |
| `npm cache` | 1.3G | `npm cache clean` — redownloads on next `npm ci` |
| the auth service `.venv` | 939M | Python venv for local dev (not needed if using Docker); `rm -rf .venv` |
| the auth service `target/debug` | 568M | `cargo clean` — Rust build artifacts (Docker builds its own) |
| WhatsApp API logs | 291M | `truncate -s 0 *.log` — logs rotate naturally |
| Camoufox/Playwright/Puppeteer browsers | 2.7G | `rm -rf ~/.cache/camoufox ~/.cache/ms-playwright ~/.cache/puppeteer` — redownload on next use |
| `/tmp/` build artifacts | ~16M | `rm -f /tmp/*.tar.gz` — old deploy payloads |

## What NOT to delete

| Item | Why |
|------|-----|
| Hermes `state.db` | Session DB — losing all chat history and memory |
| Builder profile `state.db` | Profile session DB |
| Docker images in use | Will break running containers |

## Quick reclaim sequence (default safe)
```bash
# 1. Hermes old snapshots
rm -rf ~/.hermes/state-snapshots/

# 2. Builder subagent sessions (biggest win)
rm -rf ~/.hermes/profiles/builder/sessions/

# 3. Application logs
truncate -s 0 /var/log/whatsapp-api/*.log

# 4. Package caches
uv cache clean
npm cache clean

# 5. Old deploy artifacts
rm -f /tmp/*.tar.gz
```
